# Game Design Document --- Incremental Roguelite (Core Gameplay)

## Core Concept

Idle incremental game where the player builds and evolves a system over
multiple runs.\
Progression is driven by reaching production plateaus and resetting to
unlock new structural mechanics.

------------------------------------------------------------------------

## Core Loop

1.  System generates resources automatically (idle).
2.  Production slows down due to scaling (plateau).
3.  Player resets the run.
4.  Gains Architecture Points.
5.  Invests in system branches (new mechanics).
6.  Starts a new run with a modified system.
7.  Reaches a new plateau, repeat.

------------------------------------------------------------------------

## Design Pillars

-   Idle-first gameplay (minimal active interaction)
-   Meaningful resets (new mechanics, not just bonuses)
-   Player-driven builds (non-linear progression)
-   System design over raw accumulation
-   Emergent synergies between mechanics

------------------------------------------------------------------------

## Resources

### Primary Resource

-   **Flux**: main production value

### Meta Resource

-   **Architecture Points**: gained on reset, used to unlock system
    branches

------------------------------------------------------------------------

## System Structure

### Base System (Run 0)

-   Linear production
-   Exponential upgrade costs
-   Early plateau

------------------------------------------------------------------------

## Architecture Tree (Unlocked after first reset)

Player can invest freely across multiple branches:

### 1. Production

-   Increase base output
-   Improve scaling
-   Add multipliers

### 2. Loops

-   Reinject resources into production
-   Create feedback systems
-   Enable exponential growth patterns

### 3. Derivation

-   Split resources into sub-resources
-   Create multi-layer systems
-   Enable parallel production chains

### 4. Logic

-   Conditional triggers (if X then Y)
-   Automation rules
-   Smart optimization

### 5. Time

-   Increase tick rate
-   Improve offline production
-   Temporal boosts

### 6. Rule Alteration

-   Modify formulas (costs, scaling)
-   Break standard progression curves
-   Introduce meta-level control

------------------------------------------------------------------------

## Constraints

-   Limited Architecture Points per reset
-   Increasing cost per upgrade
-   Optional incompatibilities between branches
-   Encourages specialization and hybrid builds

------------------------------------------------------------------------

## Player Actions

-   Invest points in branches
-   Choose strategic direction
-   Trigger resets

No need for constant interaction.

------------------------------------------------------------------------

## Build Diversity

Examples: - Pure production scaling - Loop-based exponential growth -
Logic-driven optimization - Time-focused idle build - Rule-breaking meta
build

------------------------------------------------------------------------

## Progression Feel

-   Early: simple accumulation
-   Mid: understanding systems
-   Late: designing complex interactions

------------------------------------------------------------------------

## Emergence

-   Hidden synergies between branches
-   Unexpected powerful combinations
-   Player experimentation encouraged

------------------------------------------------------------------------

## Goal

Optimize and evolve a self-sustaining system capable of pushing
production further each run.
